# 选课管理模块 PRD（高并发）

## 1. 模块概述

学生端选课/退课，教务员端选课统计。选课开放期间会面临高并发压力，需专项设计。

## 2. 功能列表

| 功能点 | 优先级 | 业务规则简述 | 备注 |
| :--- | :---: | :--- | :--- |
| 可选课程列表 | P0 | 学生查看可选课程；显示剩余容量 | Redis缓存 |
| 选课操作 | P0 | 乐观锁防超卖；冲突检测；限流保护 | 高并发设计 |
| 退课操作 | P0 | 退课后容量+1；可退课时间窗口限制 | |
| 已选课程查询 | P0 | 学生查看已选课程列表 | |
| 选课结果统计 | P0 | 教务员查看各课程选课人数 | |

## 3. 高并发设计

### 3.1 选课流程

```
学生点击选课
    → 限流检查（令牌桶，100 QPS）
    → 时间冲突检测（同一学生不可选相同时段课程）
    → 课程容量检查（Redis缓存）
    → 乐观锁扣减容量（UPDATE courses SET version=version+1 WHERE id=? AND version=?）
    → 写入选课记录
    → 更新Redis缓存
```

### 3.2 防超卖策略
- 课程表设 `version` 字段（乐观锁）
- 扣减容量SQL：`UPDATE courses SET selected_count=selected_count+1, version=version+1 WHERE id=:id AND version=:version AND selected_count < max_capacity`
- 若 affected_rows=0，说明容量已满或版本冲突，返回"选课名额已满，请刷新重试"

### 3.3 Redis缓存策略
- 课程列表 + 剩余容量 → Redis Hash，TTL 5分钟
- 选课成功后失效对应缓存
- 缓存未命中时回源数据库

### 3.4 限流策略
- 使用令牌桶算法，对选课/退课接口做限流
- 单用户限流：100次/秒
- 全局限流：根据服务器承载能力配置

### 3.5 冲突检测
- 同一学生不可选同一时段已选课程（按 day_of_week + period 检查）
- 不可重复选同一门课（student_id + course_id 联合唯一索引）

## 4. 数据字典

### 选课记录表 (course_selections)

| 字段名 | 类型 | 必填 | 说明 |
| :--- | :--- | :---: | :--- |
| id | INT | 是 | 主键，自增 |
| student_id | INT | 是 | 学生ID，外键 |
| course_id | INT | 是 | 课程ID，外键 |
| semester_id | INT | 是 | 学期ID，外键 |
| selected_at | DATETIME | 是 | 选课时间 |
| status | VARCHAR(10) | 是 | 状态：selected/dropped |

**唯一索引**：`uk_student_course (student_id, course_id, semester_id)` 防止重复选课
