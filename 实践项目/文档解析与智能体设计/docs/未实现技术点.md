# 未实现技术点

> 本文档记录各模块当前尚未实现、后续需补充的技术点，作为开发排期与技术债清单。
> 简历解析引擎：当前阶段（节点二：多格式解析）先跑通 PDF 主链路，Word/图片相关能力按优先级后续补充。

## 1. 大模型多模态 OCR 兜底（`_llm_ocr`）

- **位置**：`src/services/file_parse_tools.py` → `_llm_ocr`
- **现状**：空实现，仅 `return ""`，带 `TODO` 注释。
- **未实现原因**：需要 LLMClient 支持多模态（图片输入），当前 `LLMClient` 仅有纯文本 `simple_chat`，无图片能力。
- **实现方向**：
  1. 在 `src/llm/client.py` 的 `LLMClient` 增加多模态接口，支持以图片（base64 / 字节流）作为输入消息。
  2. 调用支持视觉的模型（GPT-4V、Qwen-VL、DeepSeek-VL 等），以图片 + 「提取图中全部文字」prompt 完成 OCR。
  3. 作为 OCR 第二级兜底，仅在 tesseract 结果为空/乱码时触发，控制成本与延迟。
  4. 需评估：多模态模型对中文简历 OCR 的准确率、单图成本、超时策略。

## 2. DOC 格式解析（`extract_doc`）

- **位置**：`src/services/file_parse_tools.py` → `extract_doc`
- **现状**：返回空 `text` / 空 `layout`，带 `TODO` 注释。
- **未实现原因**：老式 `.doc` 为二进制 OLE，无直接文本层，需先转换。
- **实现方向**：优先 LibreOffice `--headless --convert-to docx` 转 docx 后复用 `extract_docx`；转换失败转图片走 OCR 兜底。

## 3. docx/doc 转 PDF 统一管线（保留待定）

- **位置**：`src/services/file_parse_tools.py` → `extract_docx` / `extract_doc`
- **现状**：docx 用 python-docx 直读文本，但拿不到像素坐标（`bbox` 为 `None`）；段落/表格交叉顺序未还原。
- **方案**：docx/doc 在系统内部转 PDF，复用 `extract_pdf` 完整管线（文本层 + fitz 坐标 + 图片提取），解决「无坐标」「顺序丢失」「图片无法提取」三个问题。
- **未实施原因**：依赖系统级 LibreOffice，需先确认部署环境是否允许安装；转 PDF 存在文本准确率下降风险。
- **决策**：暂保留，待确认部署环境与「是否必须拿 docx 版式坐标」后决定「全量转 PDF」还是「混合双解析」。

## 4. 图片预处理

- **位置**：`src/services/file_parse_tools.py` → `_tesseract_ocr` 之前缺失
- **现状**：OCR 前无任何预处理，直接拿原图识别。
- **实现方向**：灰度化 → 二值化（自适应阈值）→ 去噪（中值滤波）→ 倾斜校正（deskew）→ 低 DPI 放大。依赖 OpenCV / PIL。

## 5. 图片解码校验

- **位置**：`src/services/file_parse_tools.py` → `extract_image` 之前缺失
- **现状**：损坏图片直接进 OCR，异常被 try/except 吞成空串，无明确错误信号。
- **实现方向**：PIL `Image.open` + `verify()` 校验完整性，失败返回明确错误而非空结果。

## 6. OCR 结果质量判定

- **位置**：`src/services/file_parse_tools.py` → `ocr_image`
- **现状**：仅判断 `text.strip()` 非空，tesseract 返回乱码（非空但不可用）会误判成功，不触发大模型兜底。
- **实现方向**：复用 `_garbled_ratio`，非空且乱码占比低于阈值才判定成功，否则走 `_llm_ocr` 兜底。

## 7. 非 PDF 格式的加密 / 完整性校验

- **位置**：`src/services/file_vaild_tools.py` → `validate_encrypted` / `validate_integrity`
- **现状**：仅 PDF 有实现（pypdf 检测 `is_encrypted`、逐页提取验证）；docx/doc/png/jpg 直接 `return True`，等于跳过校验。
- **实现方向**：
  - docx：OOXML 加密文件实为 OLE 容器（魔数非 `PK`），可在格式识别层拦截；或解析 `EncryptionInfo` 流。
  - doc：OLE 加密检测。
  - png/jpg：用 PIL 打开 + `verify()` 做完整性校验。

## 8. `extract_pdf_images` 消费方待定

- **位置**：`src/services/file_parse_tools.py` → `extract_pdf_images`
- **现状**：已实现「按需提取 PDF 图片二进制」，但当前无任何节点调用，属于悬空预留函数。
- **决策**：需确认产品是否要「提取文档内图片作为简历数据」（头像/作品图）。若需要，接入节点四结构化提取或数据导出；若不需要，删除。

## 9. 页眉页脚跨页重复检测（替代固定 y 阈值）

- **位置**：`src/services/document_processing_engine/layout_process.py` → `is_body`
- **现状**：`is_body` 用「顶部/底部 8%」固定阈值剥离页眉页脚；单页文档已跳过剥离，但多页文档仍会误删顶部正文（如标题、姓名）。
- **实现方向**：页眉页脚的本质特征是「多页相同位置重复出现相同内容」，改为跨页对比——若某文本块在多页同 y 区域重复出现，判为页眉/页脚再剥离，否则保留。

## 10. 模拟面试多轮追问（当前仅单轮）

- **位置**：`src/agent/mock_interview.py` → `ask` / `evaluate`，`src/agent/qa_graph.py` → `_after_evaluate`
- **现状**：追问已实现「真正生效」的交互子循环（主问题 → 作答 → 评估 → 追问 → 作答 → 评估 → 下一主问题），但每题最多追问 1 次，无 `follow_up_rounds` 计数。
- **实现方向**：
  1. 在 `QaState` 增加 `follow_up_rounds` 计数器，`evaluate` 在主问题后若仍需追问且轮数 < 上限（如 3）则继续设 `pending_follow_up`，否则清空进入下一主问题。
  2. 是否继续追问可结合「回答完整度 + 追问轮数」双重判断，避免无限追问。
- **备选方案（子代理模式）**：若将来追问需「多专家路由」（技术/行为/案例各用独立追问策略与知识库），可评估用子代理模式——把追问做成 `delegate_xxx` 工具、工具内创建子 agent。当前场景只有一个面试官角色、追问紧耦合主问题循环，子代理模式会带来上下文丢失、延迟翻倍、状态难追踪、放大 ollama 工具调用不稳定等问题，暂不采用。
