# 前端数据接口设计

> 本文档是《简历智能体产品需求文档》第 5 章（核心功能需求）与《模块 Agent 工作流模式设计》第 2.1 节（统一数据契约）的前后端对接依据，定义后端对前端开放的 REST API。后端首次设计时前端数据约定尚未冻结，本接口为本项目的数据契约基线，后续按需迭代。

## 0. 通用约定

### 0.1 域名与版本

- 基路径：`/api/v1/**`
- 所有接口均为 `application/json`（除文件上传为 `multipart/form-data`）

### 0.2 统一响应包裹

所有接口返回如下结构：

```json
{
  "code": 0,
  "message": "ok",
  "data": { }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | int | `0` 表示成功；非 0 为业务错误码（见模块前缀，如 `PARSE_*`） |
| `message` | string | 可直接展示给用户的提示信息 |
| `data` | object | 业务数据，详情见各接口 |

### 0.3 鉴权

- 登录后携带请求头：`Authorization: Bearer <token>`
- 未授权返回 `code: 401001`，`message: "未登录或登录已过期"`

### 0.4 分页统一结构

分页列表均返回：

```json
{
  "page": 1,
  "page_size": 10,
  "total": 120,
  "list": []
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `page` | int | 当前页码，从 1 开始 |
| `page_size` | int | 每页条数 |
| `total` | int | 总条数 |
| `list` | array | 当前页数据 |

### 0.5 错误码前缀

| 模块 | 前缀 |
|------|------|
| 简历解析引擎 | `PARSE_*` |
| 简历智能问答 | `QA_*` |
| 简历智能生成与优化 | `EDIT_*` |
| 用户中心与数据管理 | `USER_*` |

## 1. 简历解析引擎

### 1.1 上传简历并解析

`POST /api/v1/resumes/parse`

- `Content-Type: multipart/form-data`

请求体：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `file` | file | 是 | 简历文件（PDF/Word/图片/扫描件） |
| `name` | string | 否 | 文件自定义名，默认取源文件名 |

响应 `data`（`StructuredResume`）：

```json
{
  "resume_id": "rsm_xxx",
  "source": { "type": "pdf", "ocr_used": false, "file_type": "pdf" },
  "fields": {
    "personal":   { "name": {"value": "张三", "confidence": 0.98}, "phone": {"value": "138...", "confidence": 0.97} },
    "education":  [ {"school": "XX大学", "major": "计算机", "degree": "本科", "confidence": 0.95} ],
    "experience": [ {"org": "XX公司", "role": "后端", "start": "2021-07", "end": "2024-06", "confidence": 0.92} ],
    "skills":     [ {"name": "Python", "confidence": 0.9} ],
    "awards":     [],
    "summary":    {"value": "...", "confidence": 0.85}
  },
  "pending": [
    { "field": "experience[1].end", "reason": "低置信度", "confidence": 0.55, "status": "待确认" }
  ],
  "file_valid": true
}
```

`data.fields` 字段说明（对应 F-PARSE-003 提取字段）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `personal` | object | 个人信息（姓名/联系方式/出生年月/政治面貌/所在城市） |
| `education` | array | 教育背景（学校/专业/学历/入学毕业时间/GPA/主修课程） |
| `experience` | array | 实践经历（实习/工作/社团/项目的时间段、组织、职位） |
| `skills` | array | 技能证书（专业技能/语言能力/证书资质） |
| `awards` | array | 获奖情况（奖学金/竞赛/荣誉称号） |
| `summary` | object | 个人评价（自我认知与职业规划） |

错误码：

| 错误码 | 说明 |
|--------|------|
| `PARSE_FORMAT_ERROR` | 文件格式错误，请重新上传 |
| `PARSE_ENCRYPTED` | 文件已加密，请解除加密后上传 |
| `PARSE_CORRUPTED` | 文件已损坏，请重新导出后上传 |
| `PARSE_EMPTY` | 文件为空，请重新上传 |
| `PARSE_INTERNAL` | 系统错误，请联系管理员 |

### 1.2 确认/修正低置信度字段

`PATCH /api/v1/resumes/{resume_id}/fields`

请求体：

```json
{
  "confirmations": [
    { "field": "experience[1].end", "value": "2024-06" },
    { "field": "personal.name", "value": "张三" }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `confirmations` | array | 是 | 待确认/修正的字段列表 |
| `confirmations[].field` | string | 是 | 字段定位（对应 `pending[].field`） |
| `confirmations[].value` | any | 是 | 用户确认或修正后的值 |

响应 `data`：更新后的 `StructuredResume`。

### 1.3 查询解析状态/结果

`GET /api/v1/resumes/{resume_id}`

响应 `data`：`StructuredResume`。

| 路径参数 | 说明 |
|----------|------|
| `resume_id` | 简历 ID |

## 2. 简历智能问答

### 2.1 生成面试问题

`POST /api/v1/resumes/{resume_id}/questions`

请求体：

```json
{ "jd": "岗位描述文本（可选）", "level": "中级" }
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `jd` | string | 否 | 目标岗位 JD；缺省时基于简历内容生成通用问题 |
| `level` | string | 否 | 岗位级别：初级/中级/高级/专家；缺省默认中级 |

响应 `data`：

```json
{
  "question_list": {
    "technical": [
      { "id": "q1", "question": "...", "difficulty": "中", "references": ["experience[0]"], "answer": "...", "has_answer": true }
    ],
    "behavioral": [ { "question": "...", "difficulty": "中", "references": [], "answer": "...", "has_answer": true } ],
    "case":       [ { "question": "...", "difficulty": "中", "references": [], "answer": "...", "has_answer": true } ]
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `technical` | array | 技术问题（占 40%） |
| `behavioral` | array | 行为问题（占 30%） |
| `case` | array | 案例问题（占 30%） |
| `[].id` | string | 问题 ID |
| `[].question` | string | 问题内容 |
| `[].difficulty` | string | 难度标签：初/中/高/专家 |
| `[].references` | array | 关联的简历字段定位 |
| `[].answer` | string | 参考答案 |
| `[].has_answer` | bool | 是否存在参考答案 |

错误码：`QA_NO_EXPERIENCE`（简历信息不足，提示补充关键经历后再提问）。

### 2.2 针对性问答（多轮）

`POST /api/v1/resumes/{resume_id}/qa`

请求体：

```json
{ "session_id": "sess_xxx（可选，首轮省略）", "question": "请介绍XX项目遇到的挑战" }
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_id` | string | 否 | 会话 ID，首轮省略则服务端新建 |
| `question` | string | 是 | 用户针对简历的提问 |

响应 `data`：

```json
{
  "session_id": "sess_xxx",
  "answer": "...",
  "citations": ["experience[0]"]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `session_id` | string | 会话 ID，多轮对话需回传 |
| `answer` | string | 回答参考，强制引用简历具体段落，禁止编造 |
| `citations` | array | 引用的简历字段定位 |

### 2.3 清空对话记忆

`DELETE /api/v1/qa/sessions/{session_id}`

响应 `data`：`{ "deleted": true }`

## 3. 简历智能生成与优化

### 3.1 生成优化建议

`POST /api/v1/resumes/{resume_id}/optimize`

请求体：

```json
{
  "jd": "可选",
  "optimize_types": ["star", "quantify", "keyword", "verb", "layout", "ats", "paragraph", "length"]
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `jd` | string | 否 | 目标岗位 JD；缺省时基于简历内容生成通用建议 |
| `optimize_types` | array | 否 | 需执行的优化类型；缺省时执行全部 |

`optimize_types` 取值（对应 F-EDIT-003 ~ F-EDIT-008, 011, 012）：

| 取值 | 对应需求 | 说明 |
|------|----------|------|
| `star` | F-EDIT-003 | STAR 法则优化 |
| `quantify` | F-EDIT-004 | 量化成果生成 |
| `keyword` | F-EDIT-005 | 关键词优化 |
| `verb` | F-EDIT-006 | 主动动词替换 |
| `layout` | F-EDIT-007 | 格式排版建议 |
| `ats` | F-EDIT-008 | ATS 兼容性优化 |
| `paragraph` | F-EDIT-011 | 段落级优化建议 |
| `length` | F-EDIT-012 | 简历长度优化 |

响应 `data`（`EditSuggestion[]`）：

```json
{
  "suggestions": [
    {
      "id": "sug_001",
      "type": "STAR",
      "target": { "field": "experience[0]", "text": "原文块" },
      "before": "负责后端开发工作",
      "after": "作为后端负责人主导XX系统从0到1搭建...",
      "explain": "补全了结果量化，缺失Result要素",
      "location": "experience[0]",
      "priority": "high"
    }
  ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 建议 ID |
| `type` | string | 建议类型（STAR/QUANTIFY/KEYWORD/VERB/LAYOUT/ATS/PARAGRAPH/LENGTH） |
| `target` | object | 目标字段定位与原文块 |
| `before` | string | 修改前内容 |
| `after` | string | 修改后内容 |
| `explain` | string | 优化依据说明 |
| `location` | string | 字段定位 |
| `priority` | string | 优先级：high/medium/low |

### 3.2 应用优化

`POST /api/v1/resumes/{resume_id}/optimize/apply`

请求体：

```json
{ "suggestion_ids": ["sug_001"], "accept_all": false }
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `suggestion_ids` | array | 否 | 逐条应用时指定 ID 列表 |
| `accept_all` | bool | 是 | `true` 全部接受，忽略 `suggestion_ids` |

响应 `data`：

```json
{ "version": "v2", "resume_id": "rsm_xxx", "updated_fields": "..." }
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `version` | string | 新版本号 |

### 3.3 修改前后对比

`GET /api/v1/resumes/{resume_id}/versions/{version}/diff?base_version=`

查询参数：

| 参数 | 必填 | 说明 |
|------|------|------|
| `base_version` | 否 | 对比基准版本，缺省对比上一版本 |

响应 `data`：

```json
{
  "diffs": [
    { "field": "experience[0]", "before": "负责后端开发工作", "after": "...", "highlight": {"added": [], "removed": []} }
  ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `diffs[].field` | string | 发生变更的字段定位 |
| `diffs[].before` | string | 变更前内容 |
| `diffs[].after` | string | 变更后内容 |
| `diffs[].highlight` | object | 差异高亮（新增/删除片段） |

错误码：`EDIT_EMPTY_RESUME`（简历内容为空或信息严重不足）。

## 4. 用户中心与数据管理

### 4.1 账户管理

| 方法 | 路径 | 说明 | 请求体/响应 |
|------|------|------|--------------|
| POST | `/api/v1/auth/register` | 注册 | `{ phone/email, password, code }` → `{ token, user }` |
| POST | `/api/v1/auth/login` | 登录 | `{ account, password }` → `{ token, user }` |
| POST | `/api/v1/auth/logout` | 登出 | → `{ success: true }` |
| GET | `/api/v1/users/me` | 个人信息 | → `{ user }` |
| PATCH | `/api/v1/users/me` | 更新个人信息 | `{ nickname, avatar, contact, job_intention }` |
| PUT | `/api/v1/users/me/password` | 修改密码 | `{ old_password, new_password }` |

`user` 字段：`{ id, nickname, avatar, phone, email, job_intention }`

登录/注册入口参考（支持微信/飞书第三方快捷登录，具体流程后续补充）。

### 4.2 简历版本管理

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/resumes/{resume_id}/versions` | 版本列表（分页） |
| GET | `/api/v1/resumes/{resume_id}/versions/{version}` | 单个版本详情 |
| POST | `/api/v1/resumes/{resume_id}/versions` | 新建版本 |
| PUT | `/api/v1/resumes/{resume_id}/versions/{version}` | 编辑版本 |
| DELETE | `/api/v1/resumes/{resume_id}/versions/{version}` | 删除版本 |
| POST | `/api/v1/resumes/{resume_id}/versions/rollback/{version}` | 回退到指定版本 |
| GET | `/api/v1/resumes/{resume_id}/export` | 导出简历（下载） |

列表项字段：`{ version, created_at, optimize_log, note }`。

### 4.3 求职记录管理

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/jobs` | 记录列表（分页） |
| POST | `/api/v1/jobs` | 新增记录 |
| PATCH | `/api/v1/jobs/{id}` | 更新记录 |
| DELETE | `/api/v1/jobs/{id}` | 删除记录 |
| GET | `/api/v1/jobs/board` | 按状态汇总的进度看板 |

记录字段：`{ id, company, position, status, date, note }`

`status` 枚举：`待投递/已投递/面试中/已录用/已拒绝`。

查询参数：`?status=面试中&page=1&page_size=10`

进度看板 `data`：

```json
{
  "board": {
    "待投递": 5, "已投递": 12, "面试中": 3, "已录用": 1, "已拒绝": 8
  }
}
```

### 4.4 数据导出 / 删除 / 统计反馈

| 方法 | 路径 | 说明 | 请求体/响应 |
|------|------|------|--------------|
| POST | `/api/v1/users/me/export` | 导出全部数据 | → 下载文件（JSON/CSV） |
| DELETE | `/api/v1/users/me/data` | 一键删除全部数据 | `{ confirm: true }`（二次确认防误删） |
| GET | `/api/v1/users/me/stats` | 使用统计 | → 见下 |
| POST | `/api/v1/feedback` | 提交反馈 | `{ content, screenshot(可选) }` |

使用统计 `data`：

```json
{
  "stats": { "parse_count": 20, "edit_count": 12, "qa_count": 35 }
}
```

## 5. 前端可直接复用的数据类型（TypeScript 建议）

```ts
interface Field<T> { value: T; confidence: number }

interface PendingItem {
  field: string;
  reason: string;
  confidence: number;
  status: "待确认" | "已确认";
}

interface ResumeSource {
  type: "pdf" | "docx" | "doc" | "png" | "jpg";
  ocr_used: boolean;
  file_type: string;
}

interface StructuredResume {
  resume_id: string;
  source: ResumeSource;
  fields: {
    personal: Record<string, Field<string>>;
    education: Array<Record<string, Field<any>>>;
    experience: Array<Record<string, Field<any>>>;
    skills: Array<Field<string>>;
    awards: any[];
    summary: Field<string>;
  };
  pending: PendingItem[];
  file_valid: boolean;
}

interface ApiResponse<T> {
  code: number;
  message: string;
  data: T;
}

interface PageData<T> {
  page: number;
  page_size: number;
  total: number;
  list: T[];
}
```
