# 模块 Agent 工作流模式设计

> 本文档是《简历智能体产品需求文档》第 5 章（核心功能需求）与第 7 章（系统架构）的技术落地依据，定义各功能模块的 Agent 编排方式、数据契约与模块间打通机制。

## 1. 概念约定

| 术语 | 定义 |
|------|------|
| 编排范式 | 业务节点/步骤的组织与执行方式：串行链、路由、ReAct |
| 设计模式 | 编排范式下的具体实现策略：交接模式、路由模式、SKILL |
| 业务节点 | 一个最小可执行的处理单元，对应一个功能或子步骤 |
| SKILL | 可复用的领域处理单元，有明确的输入/输出契约 |
| 数据契约 | 模块间传递的结构化数据结构，是模块打通的唯一依据 |

## 2. 设计总览

### 2.1 统一数据契约（打通的关键）

`StructuredResume`（结构化简历）由简历解析引擎唯一产出，是简历智能问答、简历智能生成与优化两个上层模块的唯一数据来源，避免各模块重复解析。

```json
{
  "resume_id": "xxx",
  "source": { "type": "pdf", "ocr_used": false },
  "fields": {
    "personal":   { "name": {"value": "张三", "confidence": 0.98}, "phone": {"value": "138...", "confidence": 0.97} },
    "education":  [ {"school": "XX大学", "major": "计算机", "degree": "本科", "confidence": 0.95} ],
    "experience": [ {"org": "XX公司", "role": "后端", "start": "2021-07", "end": "2024-06", "confidence": 0.92} ],
    "skills":     [ {"name": "Python", "confidence": 0.9} ],
    "awards":     [],
    "summary":    {"value": "...", "confidence": 0.85}
  },
  "pending": [ {"field": "experience[1].end", "reason": "低置信度", "confidence": 0.55} ]
}
```

字段统一以 `value + confidence` 包装；解析后单独输出 `pending` 待确认清单。

### 2.2 模块间数据流

```
简历文件
   │
   ▼
简历解析引擎 ──(StructuredResume)──► 简历智能问答
   │                                    │ 输出：QuestionList / AnswerReference
   │                                    ▼
   └──────────(StructuredResume)──► 简历智能生成与优化
                                         │ 输出：EditSuggestion[] + 新版本
                                         ▼
                                    用户中心（版本管理 / 数据导出）
```

### 2.3 统一 Agent 运行时（贯穿机制）

所有模块共用一套运行时能力，是「打通」的技术底座：

| 能力 | 说明 |
|------|------|
| 路由（Router） | 依据意图/条件将请求分发到不同 SKILL |
| 工具调用（Tool/SKILL） | 可复用的领域处理单元，统一输入/输出契约 |
| 记忆（Memory） | 多轮上下文持久化，敏感信息脱敏 |
| 状态管理（State） | 工作流状态持久化，支持断点续跑与回退 |

## 3. 简历解析引擎

对应需求：F-PARSE-001 ~ F-PARSE-004。

- **业务节点**：文件校验 → 多格式解析 → 复杂排版还原 → 结构化信息提取 → 解析结果校验与补全
- **编排范式**：串行链（Pipeline），上一节点的输出是下一节点的输入
- **设计模式**：交接模式（Handoff）——各节点顺序交接，任一节点失败即中断
- **数据契约**：输入 `简历文件`，输出 `StructuredResume`
- **技术要点**：
  - 混合解析：规则引擎（正则/字段词典）→ OCR（扫描件兜底）→ 大模型文档理解（复杂版式重构）
  - 每个字段产出置信度，作为校验与下游「待确认」的判定依据
  - 基于文件指纹（hash）做解析缓存，保证高并发下的解析速度

## 4. 简历智能问答

对应需求：F-QA-001 ~ F-QA-004。

- **业务节点**：意图识别 → 路由分发 → 知识检索（RAG）→ 结合简历生成回答
- **编排范式**：路由（Router）+ RAG
- **设计模式**：路由模式 + SKILL
  - SKILL-1 面试问题生成：输入 `StructuredResume + JD`，输出三维度问题（技术面/行为面/案例面）+ 参考答案 + 难度标签
  - SKILL-2 针对性问答：输入 `用户问题 + StructuredResume`，检索简历段落并生成回答参考
  - SKILL-3 难度分级：按岗位级别（初级/中级/高级/专家）调整问题深度
- **数据契约**：输入 `StructuredResume`，输出 `QuestionList` / `AnswerReference`
- **技术要点**：
  - 意图识别（BERT）判断用户问题类型（技术/行为/案例/通用）
  - RAG：简历向量化后检索，回答强制引用简历具体段落，禁止编造
  - 多轮记忆：持久化对话上下文，支持记忆清理与敏感信息脱敏

## 5. 简历智能生成与优化

对应需求：F-EDIT-001 ~ F-EDIT-012。

- **业务节点**：信息获取 → 简历生成/逐条优化（STAR、量化、关键词、动词、排版、ATS、段落、长度）→ 一键应用与对比
- **编排范式**：ReAct + 串行链
- **设计模式**：交接模式 + SKILL
  - SKILL-1 简历生成：依据用户输入/`StructuredResume` 生成整份简历
  - SKILL-2 STAR 优化、SKILL-3 量化成果、SKILL-4 关键词、SKILL-5 动词替换、SKILL-6 排版、SKILL-7 ATS 检测、SKILL-8 段落优化、SKILL-9 长度优化
- **数据契约**：输入 `StructuredResume` / 用户输入，输出 `EditSuggestion[]` + 新版本
- **技术要点**：
  - ReAct：对每条优化建议执行「分析 → 生成 → 校验」循环，保证建议可追溯（原文 → 优化后）
  - 各优化 SKILL 以串行链顺序执行，产出统一的 `EditSuggestion[]`
  - 版本化：每次优化生成新版本号，支持回退与对比

## 6. 用户中心与数据管理

对应需求：F-USER-001 ~ F-USER-005。

- **编排范式**：无复杂 Agent，标准 CRUD + 状态管理
- **技术要点**：复用统一运行时中的状态管理，维护简历版本、求职记录、数据导出/删除

## 7. 模块间打通的技术核心要点（汇总）

1. **唯一数据源**：`StructuredResume` 由解析引擎唯一产出，问答/优化只读不重新解析。
2. **向量化检索**：简历字段写入 Milvus，供问答 RAG 与优化的关键词对标复用。
3. **置信度贯穿**：解析产出的 `confidence` 一路传递到问答/优化，低置信度统一进入 `pending` 待确认。
4. **统一运行时**：路由、SKILL 调用、记忆、状态管理四个能力全局复用，避免各模块重复造轮子。
5. **版本化**：优化模块每次修改产出新版本，用户中心统一管理版本与回退。
